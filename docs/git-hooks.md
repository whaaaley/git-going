# Git Hooks

Wiring `uncommitted` and `validate` into a repository.
Both run from git hooks. `treesize` does not, and is covered in [Claude Code Hook](claude-code.md).

## Check core.hooksPath First

Git allows one hooks directory per repository, named by `core.hooksPath`.
Check whether the repository already sets one before you change it.
Pointing `core.hooksPath` somewhere else silently stops the existing hooks from running, with no warning and no error.

```sh
git config core.hooksPath
```

If that prints a path, the repository already has a hooks directory.
Add the lines below to the hook files already in that directory rather than changing the setting.

If it prints nothing, create a directory and point git at it:

```sh
mkdir -p .githooks
git config core.hooksPath .githooks
```

## Hook Files

`.githooks/commit-msg`:

```sh
#!/usr/bin/env bash
git-going validate --file "$1"
```

`.githooks/post-commit`:

```sh
#!/usr/bin/env bash
git-going uncommitted
```

`.githooks/post-rewrite`:

```sh
#!/usr/bin/env bash
git-going uncommitted
```

Make them executable:

```sh
chmod +x .githooks/commit-msg .githooks/post-commit .githooks/post-rewrite
```

## validate

Reads a commit message and checks the first line against the subject rules in [Config](config.md).
The path comes from the argument git passes the `commit-msg` hook.
A bare positional path works too, so `git-going validate "$1"` behaves the same as `--file "$1"`.
With no path it reads the message on stdin.

It exits 1 and names each broken rule when the subject does not pass, which fails the commit.
A subject beginning with `Merge ` or `Revert ` is generated by git and passes without being checked.

## uncommitted

Counts the tracked changes between the working tree and HEAD.
It warns when either the file count or the changed-line count reaches its threshold.
The line count is insertions plus deletions, and either count trips the warning on its own.
Untracked files are not counted.

It exits 0 whether or not it warns, because the warning is advice and must not fail the commit that triggered it.
A malformed `git-going.json` is reported on stderr and the hook still exits 0 for the same reason.
